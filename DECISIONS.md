# DECISIONS.md — Shanky lane assumptions & architectural decisions

This file records all assumptions and decisions made during the autonomous execution of Shanky's lane in accordance with `SAKHILINE_BUILD.md`. Format: `A-<n>: <assumption> — <why> — <how to reverse>`.

## Logged Assumptions

- **A-0: Implementation Authorization for Shanky Lane** — The repository owner explicitly prompted to build Shanky's lane phase-by-phase per `SAKHILINE_BUILD.md`. This satisfies the human G2 authorization precondition for Shanky's core backend/data/eval lane only, with strictly synthetic data and zero paid cloud spend. — *How to reverse:* Revert git commits back to baseline tag/commit.
- **A-1: Primary Language Hindi with English Terms** — Authoring scenarios and mock extraction rules in mixed Hindi/English (Hinglish) as specified in `SAKHILINE_BUILD.md §1`. Language negotiation and provider language codes belong to Johny's speech layer. — *How to reverse:* Update evaluation scenarios in `eval/fixtures/` and mock extraction regexes in `apps/api/src/extraction/mock.ts`.
- **A-2: Identity Contract and Fixture Verification** — Since production OIDC provider is undecided, implement the `IdentityVerifier` interface with a `FixtureVerifier` for `APP_MODE=local` / testing. Live mode (`APP_MODE=live`) strictly rejects fixture verification and returns 401. — *How to reverse:* Replace `FixtureVerifier` with an OIDC JWT/session verifier in `apps/api/src/auth/identity.ts`.
- **A-3: Extraction Provider Abstraction & Deterministic Mock** — LLM vendor is unselected; implement `ExtractionProvider` interface with a deterministic regex-based `MockExtractionProvider` and an `HttpStubExtractionProvider` that throws `NOT_CONFIGURED`. — *How to reverse:* Supply a real LLM adapter implementation fulfilling `ExtractionProvider` in `apps/api/src/extraction/`.
- **A-4: Resource and String Limits** — Strict limits: Context TTL = 600s (10 minutes); visit note <= 2,000 Unicode code points; return reason <= 1,000 code points; transcript <= 16,000 code points; idempotency key 16–128 characters alphanumeric/dot/dash/underscore. — *How to reverse:* Adjust constants in `packages/contracts/src/visit.ts` and database migrations.
- **A-5: Domain Fields & Zero Clinical Thresholds** — Blood pressure (systolic/diastolic in mmHg), Hemoglobin (normalized decimal string g/dL), TT dose mention (reported text), Follow-up date (ISO YYYY-MM-DD), and optional note. No diagnostic warnings, alert thresholds, or triage levels are calculated or returned. — *How to reverse:* Expand or constrain schema in `packages/contracts/src/visit.ts` after medical domain review.
- **A-6: Standalone Package Architecture** — Because teammate Johny owns root `package.json`, lockfile, and workspace configuration, Shanky's packages (`packages/contracts`, `packages/db`, and future `eval`) manage their own dependencies standalone. — *How to reverse:* When Johny sets up root npm workspaces, hoist common dependencies to the monorepo root.
- **A-7: API Package Shim Ownership** — `apps/api/package.json` belongs to Johny. If not present at Phase 3, a minimal test shim (`@sakhiline/api` with express, zod, vitest, supertest) will be used and documented in `HANDOFF.md` for Johny to take over. — *How to reverse:* Johny adopts or replaces `apps/api/package.json`.
- **A-8: Evaluation Database Isolation** — Evaluation tables (`evaluation_run`, `evaluation_result`) are deliberately isolated with zero foreign keys to clinical/visit tables. In production, a restricted PostgreSQL role (`sakhiline_eval`) with grants limited strictly to evaluation tables will be configured; in local/test mode, they share the test database without foreign keys. — *How to reverse:* Run migration to add cross-schema foreign keys if evaluated visits ever need direct joins.
- **A-9: Ephemeral Proposal Store & Two-Stage Revision Safety** — Extracted proposals are cached ephemerally in-memory by proposal ID; upon `POST /visits/:id/proposals/:pid/accept`, the proposal's `baseRevision` is verified against the visit's current revision. If the visit's revision has changed (via concurrent edit or review), the accept request fails with 409 `STALE_REVISION` and the draft is untouched. — *How to reverse:* Back proposals by Redis or database table if horizontal API multi-instance scaling is required without session stickiness.
- **A-10: Exact Canonical Matching & Zero Fuzzy Pass** — Hemoglobin strings are normalized to canonical single-decimal string (`"9"` -> `"9.0"`) and integers/ISOs are strictly compared. No fuzzy numeric tolerances are permitted in scoring. All failures (schema validation, provider timeouts/500s) remain in metric denominators to guarantee statistical integrity without survival bias. — *How to reverse:* Modify `eval/src/scorer.ts` if clinical evaluation tolerance bands are later approved by medical council.
